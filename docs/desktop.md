# Desktop helper

The macOS backend captures a selected display as JPEG snapshots or live H.264 video and injects pointer, text, scroll, and named keyboard input. A bounded foreground accessibility-tree command redacts secure text fields. The native display selector uses the helper's live catalog; changing displays clears input leases and frame freshness and ends active input/video. A missing display fails instead of silently switching capture. See [video.md](video.md) for encoding, native decoding, and stream bounds.

Windows has a PowerShell/.NET helper at `helpers/windows/DesktopHelper.ps1`: selected-display JPEG capture and SendInput, with active input desktop checks. A bounded UI Automation foreground tree excludes password values and requires the foreground process to belong to the interactive OS user. Point `CONTROL_PLANE_DESKTOP_HELPER` at that file; the host launches it with Windows PowerShell. It requires execution under the interactive user and an execution policy that permits the script. Secure desktops and input into higher-integrity applications remain unavailable. Sign the script before distribution. Real Windows execution has not been verified here.

Linux GNOME Wayland support is implemented in `helpers/linux/wayland_helper.py` and its persistent user service, using XDG RemoteDesktop/ScreenCast portals, PipeWire/GStreamer capture, and portal input. Display selection is restricted to monitors granted by local consent. A bounded AT-SPI foreground tree requires accessibility already enabled locally and an unlocked session; password content is redacted. H.264 is available when the required plugins exist. Setup and local consent are documented in [wayland.md](wayland.md). The current contracts pass on macOS; earlier lifecycle contracts also passed in a Linux container. A real GNOME compositor session has not been exercised here.

The separate GNOME X11 development fallback remains at `helpers/linux/desktop_helper.py`, requiring xrandr, ImageMagick `import`, xdotool, and gdbus. It checks the GNOME lock service and explicitly refuses Wayland. It enumerates displays but rejects negative-origin capture layouts. Windows capture/input and GNOME capture/input still need tests on actual target desktops.

Build with `sh helpers/macos/build.sh`, then set `CONTROL_PLANE_DESKTOP_HELPER` to the absolute `helpers/macos/build/control-plane-desktop` path before starting the host. Grant Screen Recording and Accessibility permissions to the helper in System Settings. Use a stable Developer ID signature for distribution; the development script uses an ad-hoc signature unless `SIGNING_IDENTITY` is set. The helper must run as the logged-in desktop user, never as root or a system service.

Helpers support `status`, `frame`, `action`, and `accessibility` where available. The persistent JSONL command channel preserves authorized sessions; the H.264 channel uses binary CPV1 packets. Wayland consent is requested only by the explicit local authorization command. Remote commands never bypass permission prompts. Locked or missing GUI sessions fail closed.

The host gives one controller a renewable 15-second lease. Input requires a successful screenshot less than 5 seconds old and its matching `geometry_version`. Geometry is rechecked in the helper immediately before input. Coordinates refer to the selected display's reported input dimensions; the helper maps them to the OS coordinate space. Emergency stop clears all leases. An input already posted to the OS cannot be retracted.

Permissions and lock-state behavior require testing on a signed app in an actual graphical user session. Successful compilation alone does not verify capture or input authorization.
