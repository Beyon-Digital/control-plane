# Native Apple clients

Requirements: Xcode with Swift 6 or later, macOS 15+, iOS/iPadOS 18+.

```sh
swift test --package-path apple
swift run --package-path apple ControlPlaneApp
python3 apple/generate_project.py
xcodebuild -skipPackagePluginValidation -project apple/ControlPlane.xcodeproj -scheme ControlPlane -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO build
```

Open `ControlPlane.xcodeproj` for device builds. Set your development team and a unique bundle identifier before installing on a physical device. The Xcode app compiles shared sources directly; the Swift package exposes the same client library for tests and other integrations. Regenerate the project after adding source files.

Choose **Connect a machine**, enter its HTTPS gateway address, and pair using the one-time secret printed or generated by the host administrator. The discovery button can find Bonjour advertisements; it supplies address hints and does not establish trust. A team invitation creates a separate member; a member enrollment adds another device to that member. Credentials and the device's private key are stored in Keychain. A private server CA requires its independently verified administrator fingerprint. The client never disables TLS verification. HTTP is permitted only for loopback development.

On macOS, **Start local host…** selects a workspace directory, launches the packaged host on loopback, and pairs this app automatically. The direct-distribution Mac app is intentionally not App Sandboxed because it supervises local coding agents. It looks for the host binary in `CONTROL_PLANE_HOST_BINARY`, app resources, or a development checkout's `target/debug`. Host data is stored under `~/Library/Application Support/ControlPlane/Host`; the worker survives closing the app and is reconnected using its saved device credential and verified host identity. Remote phones require explicitly configuring a TLS private-network listener through the host CLI; the automatic local launch exposes loopback only.

The client supports the authenticated JSON gateway, optional native HTTP/2 gRPC requests and event subscriptions, and WSS terminal/video channels. TLS connections enroll a client certificate from a signed CSR and require both that certificate and the device token. Connecting within seven days of certificate expiry renews it. SwiftTerm provides ANSI terminal emulation, binary-safe replay, cell resizing, and bounded input queues. APNs registration is opt-in and requires a provisioned build and configured push gateway. Desktop control offers display selection and VideoToolbox-decoded H.264 live video on supported backends, with on-demand snapshots as an explicit fallback. See [video.md](../docs/video.md) for framing, capabilities, and verification.

Clients support session creation, streaming history/reconnect, prompts, interruption, archival, provider decisions, workspace browsing/editing with optimistic concurrency, Git diff/commit/push and worktree creation, binary file transfer, provider history import, shell attach/input, desktop screenshots/input, host emergency stop, team invitations, member/device revocation, and explicit viewer/operator session grants. Administrators can inspect usage and configure quotas/retention. Mac update controls verify signed manifests through the bundled updater and drain local workers before opening an installer; publisher trust is configured at build time. See [releases.md](../docs/releases.md) for release prerequisites and recovery.

**Models** configures custom OpenAI-compatible model profiles or ChatGPT plan
accounts through dynamic registration. **Orchestrator** uses the selected profile
for streaming chat and scoped agent coordination on the selected host. API keys
and OAuth tokens stay in this device's Keychain; profiles contain only metadata.
See [orchestrator.md](../docs/orchestrator.md) for sign-in, permission boundaries,
and device acceptance requirements.

For a shared machine, connect to the account-specific broker base URL (for
example `https://machine:9847/accounts/alice`). Session creation offers configured
WSL distributions alongside the host OS. Selecting WSL preserves Linux workspace
paths and probes providers in that exact distro/user. Desktop controls continue
to operate the Windows desktop. Video, terminal, and event WebSockets retain the
selected account base path; credentials stay in request headers, never URLs.

## iOS acceptance tests

The generated `ControlPlane-iOSTests` scheme runs client logic and UI tests inside
the actual iOS app. `python3 scripts/test-ios.py` creates and cleans up a dedicated
iPhone 16 Plus simulator and supplies a disposable loopback host for native gRPC
and file transfer. Build the Rust binaries first. Pass `--device <exact-UDID>` and
`--team <development-team>` to test an available paired iPhone with normal signing.
Tests use `dev.controlplane.acceptance` to keep their preferences separate from a
normal installation. See [CI and device acceptance](../docs/ci.md) for commands,
result bundles, physical-device limitations, and GitHub runner setup.
