# Multi-user machine broker

`control-plane-broker` exposes one TLS gateway and gRPC endpoint for independently
supervised OS-user workers. It routes requests; it never starts an agent as root,
impersonates an account, or stores a shared provider credential.

Every worker keeps its existing database, provider login, workspace roots,
devices, and member identity. Its IPC listener still requires its own device
token. Alice's token cannot authenticate against Bob's worker, regardless of
which URL or gRPC metadata a client supplies.

## Register each member's worker

Build the release binaries, then run as **each member's actual OS account**:

```sh
python3 scripts/install-worker.py \
  --binary /absolute/path/to/control-plane-host \
  --account alice --name Alice \
  --data /home/alice/.local/share/control-plane \
  --workspace-root /home/alice/projects \
  --broker-url https://machine.example:9847/accounts/alice
```

On macOS use a data path under that member's home. The installer creates a
LaunchAgent on macOS, a systemd user service on Linux, and a current-user
interactive scheduled task on Windows. `--print-only` previews the generated
configuration. No user account, password, WSL distribution, screen permission,
or input permission is created by installation. Existing service configurations
are not overwritten.

For manual startup on Unix, create a private socket directory and run:

```sh
mkdir -p /home/alice/.local/share/control-plane/ipc
chmod 700 /home/alice/.local/share/control-plane/ipc
control-plane-host --data /home/alice/.local/share/control-plane serve \
  --workspace-root /home/alice/projects \
  --ipc-socket /home/alice/.local/share/control-plane/ipc/worker.sock
```

IPC mode opens **no TCP listeners**. It creates `worker.sock` for HTTP/WebSocket
and `worker.grpc.sock` for gRPC, both mode `0600` inside an owner-only directory.
The worker accepts its own UID or the configured broker UID (default root/0).
The broker verifies socket ownership, permissions, and connected peer UID. A
stale socket is replaced only when its owner matches and connecting confirms
that it is no longer serving. A live socket is never replaced.

For a non-root development broker, set `--broker-uid` to that broker's UID. It
also needs OS permission to reach every registered account socket; do not solve
that by making sockets world-readable. Production root/System routing keeps
the workers and agents unprivileged.

Print the account registration under the same OS identity:

```sh
control-plane-host --data /home/alice/.local/share/control-plane worker-info \
  --account alice --name Alice
```

Give the resulting JSON to the administrator. It contains paths and an OS
identity, not provider credentials or device tokens.

## Machine registry and listener

An administrator creates a protected registry:

```json
{
  "accounts": [
    {
      "id": "alice",
      "name": "Alice",
      "endpoint": {
        "transport": "unix",
        "http_socket": "/home/alice/.local/share/control-plane/ipc/worker.sock",
        "grpc_socket": "/home/alice/.local/share/control-plane/ipc/worker.grpc.sock",
        "uid": 1000
      }
    }
  ]
}
```

Use the actual UID from `worker-info`. Add one entry per OS account. On Unix the
registry must be owned by root or the broker user and must not be writable by
other users. Its parent directories must also prevent replacement by another
user. Protect the broker executable and TLS key with the same ownership rules.

```sh
control-plane-broker --config /etc/control-plane/broker.json \
  --listen 0.0.0.0:9847 --grpc-listen 0.0.0.0:9848 \
  --tls-cert /etc/control-plane/server.pem \
  --tls-key /etc/control-plane/server.key
```

Remote listeners require TLS. `--client-ca` can additionally require client
certificates on gRPC. The existing private-network and certificate-trust setup
applies. The broker opens only registry-approved local IPC endpoints and checks
their OS identity on every new connection.

The native clients connect to **`https://machine.example:9847/accounts/alice`**.
HTTP, terminal events, desktop video, and other WebSockets preserve that base
path. gRPC clients connect to the machine endpoint and send both `x-account-id`
and the account worker's `x-device-token` metadata. Routing metadata grants no
authority by itself.

Enrollment secrets are generated by the account owner or a previously enrolled
administrator of that worker, then paired through that account's URL. Revocation
and audit history remain account-local. The broker does not expose a public
directory of users or grant one worker's administrator access to other workers.
Removing a registry entry requires a broker restart; revoking a device takes
effect inside its worker without restarting the broker.

## Windows

Windows worker IPC uses named pipes instead of Unix sockets:

```powershell
control-plane-host.exe --data "$env:LOCALAPPDATA\ControlPlane" serve `
  --workspace-root C:\Projects `
  --ipc-pipe '\\.\pipe\control-plane-alice' `
  --broker-sid S-1-5-18
```

The broker SID defaults to LocalSystem. Pipe DACLs permit only the worker owner
and configured broker identity; remote pipe clients are rejected. The gRPC pipe
adds `-grpc`. The broker checks the pipe server process SID, and client QoS
permits identification without allowing a user worker to impersonate the broker.
Use `worker-info --account alice --ipc-pipe ...` to obtain the actual SID and
registry entry. Do not substitute a display name for a SID.

Run the machine broker using a protected LocalSystem startup scheduled task or
an existing service supervisor. The console executable does not implement the
Windows Service Control Manager protocol, so do not register it directly with
`sc create`. Store its executable under an administrator-protected installation
directory and its registry/key under a protected ProgramData directory. Registry
validation rejects writable/untrusted owners, reparse points, and unsafe ACLs.

## Verification

Rust integration tests cover real Unix IPC, separate worker databases, incorrect
UIDs/tokens, pairing, gRPC account metadata, WebSocket replay, and revocation.
`scripts/broker-os-smoke.py` additionally runs two existing unprivileged Linux
identities in an isolated container/CI; it creates no accounts and invokes no
providers. Windows pipe execution still needs acceptance testing on Windows.

## Device certificates

Every TLS broker requires `--client-ca /protected/path/worker-device-cas.pem`.
Concatenate the **public** `pki/device-ca.pem` from each registered worker after
verifying its origin with that OS account's administrator. Never copy a worker's
`device-ca-key.pem` into the broker. Restart the broker after adding a worker CA.

These CAs authenticate client devices. They are separate from the CA that signs
the broker's server certificate. Provide the server CA/fingerprint to clients
through a trusted channel. Bonjour results and `/.well-known/control-plane-identity`
never establish server trust. New native pairing includes a CSR; pre-certificate
clients must upgrade or enroll before remote access works. Loopback plaintext
remains a development transport.
